# gost-c

Перенос пользовательского стека Sparta (клиент, relay-узел, агент и C API для
iOS) находится в [sparta/](sparta/README.md). Найденные проблемы и исправления:
[sparta/AUDIT.md](sparta/AUDIT.md).

Реализация на **C17** выбранных функций [GOST](https://github.com/go-gost/gost):
HTTP-прокси, SOCKS5, перенаправление TCP/UDP и TCP-цепочки через HTTP/SOCKS5.
Исполняемый файл не зависит от Go и сторонних библиотек: нужны POSIX-сокеты
и pthreads. Проверено на Linux.

## Сборка и проверки

```sh
cd /workspace/calc
make -j2
make test
# Отдельная пересборка с AddressSanitizer и UndefinedBehaviorSanitizer:
make sanitize
# Вернуть обычную сборку после санитайзеров:
make clean
make -j2
```

Нужны C-компилятор и GNU Make; для тестов — Python 3.8+ со стандартной
библиотекой. Проверка совместимости с curl выполняется, если curl установлен.
Тесты поднимают локальные серверы и передают настоящие TCP/UDP-данные;
доступ к Интернету не требуется. Среда запуска должна разрешать loopback-сокеты.

Результат сборки: `build/gost-c`. Справка: `build/gost-c --help`.

## Запуск

HTTP и HTTPS через CONNECT:

```sh
./build/gost-c -L http://127.0.0.1:8080
curl --noproxy '' -x http://127.0.0.1:8080 http://example.com/
curl --noproxy '' -x http://127.0.0.1:8080 https://example.com/
```

SOCKS5 с авторизацией, CONNECT и UDP ASSOCIATE:

```sh
./build/gost-c -L socks5://user:pass@127.0.0.1:1080
curl --noproxy '' --proxy socks5h://user:pass@127.0.0.1:1080 http://example.com/
```

Автоматическое определение HTTP/SOCKS5 на одном порту:

```sh
./build/gost-c -L auto://127.0.0.1:8080
# Короткая форма совместима с тем же режимом:
./build/gost-c -L 127.0.0.1:8080
```

Перенаправление TCP и UDP с отдельными сеансами для разных клиентов:

```sh
./build/gost-c \
  -L tcp://127.0.0.1:9000/192.168.1.10:80 \
  -L udp://127.0.0.1:5353/192.168.1.10:53
```

Цепочка TCP: клиент → этот процесс → HTTP-прокси → SOCKS5-прокси → назначение.
Все `-F` образуют общую цепочку для всех TCP-слушателей этого процесса:

```sh
./build/gost-c \
  -L http://127.0.0.1:8080 \
  -F http://user:pass@proxy1.example:3128 \
  -F socks5://alice:secret@proxy2.example:1080
```

Для IPv6 нужны скобки: `-L 'socks5://[::1]:1080'`,
`-L 'tcp://[::1]:9000/[::1]:80'`.
Спецсимволы в логине/пароле кодируются как `%40`, `%3A`, `%25` и т. п.
Пустой адрес (`:8080`) или `*` означает все интерфейсы IPv4;
`[::]` — все интерфейсы IPv6, отдельно от IPv4.
Порт слушателя `0` выбирает свободный порт; реальный адрес выводится в stderr.

## Реализованное поведение

| Функция | Поддержка |
| --- | --- |
| HTTP/1.0, HTTP/1.1 | Абсолютный URI и origin-form с Host, обычные методы, CONNECT |
| Тело HTTP-запроса | Content-Length, chunked, трейлеры, Expect: 100-continue |
| HTTP-авторизация | Proxy-Authorization: Basic, ответ 407 при отказе |
| SOCKS5 | IPv4, IPv6, доменное имя, CONNECT, UDP ASSOCIATE |
| SOCKS5-авторизация | Без авторизации либо RFC 1929 username/password |
| Перенаправление портов | TCP и UDP, несколько `-L` |
| Цепочки | Несколько `-F` HTTP CONNECT/SOCKS5 с авторизацией для TCP |
| TCP-поток | Двоичные данные, backpressure, half-close |
| Завершение | SIGINT/SIGTERM закрывают слушателей и активные сеансы |

HTTP-прокси обрабатывает **один HTTP-запрос на клиентское соединение** и
выставляет `Connection: close`. CONNECT работает как двусторонний туннель.
Авторизация прокси и заголовки, перечисленные в Connection, не передаются
конечному HTTP-серверу. Неоднозначные Content-Length/Transfer-Encoding
отклоняются. Байты после тела первого запроса не пересылаются.

UDP ASSOCIATE действует, пока открыто управляющее TCP-соединение и не истёк
таймаут. Источник датаграмм должен иметь IP управляющего соединения;
порт берётся из запроса или фиксируется первой корректной датаграммой.
Ответы принимаются через UDP-сокеты, подключённые к конкретным назначениям.
UDP-фрагменты SOCKS5 (`FRAG != 0`) отбрасываются.

По умолчанию: простой соединения/UDP-сеанса — 60 с, установка TCP-соединения —
10 с, одновременно не более 256 TCP-клиентов, 32 слушателей, 8 звеньев цепочки.
Для каждого UDP-слушателя и каждой SOCKS5 UDP-ассоциации допускается до
128 активных UDP-потоков. После заполнения новые потоки отбрасываются до
освобождения места. Размер HTTP-заголовков ограничен 32 КиБ.

```sh
./build/gost-c -L socks5://127.0.0.1:1080 \
  --timeout 120 --connect-timeout 5 --max-clients 512
```

Имена разрешаются системным `getaddrinfo`. Для UDP используется первый
доступный адрес; отсутствие ответа от удалённого UDP-сервера не вызывает
переключение на другой адрес DNS. Системное разрешение DNS может блокироваться
дольше `--connect-timeout`; этот параметр ограничивает сетевое подключение.

## Границы совместимости

Это перенос выбранных функций, а не полная замена GOST v3. YAML/JSON-конфиги
и API GOST, TLS-слушатели, WebSocket/Upgrade, HTTP/2, QUIC, Shadowsocks,
TUN/TAP, плагины, прозрачный/обратный прокси, балансировка и метрики
не реализованы. Программа отклоняет неподдерживаемые параметры и схемы URL.
UDP через `-F` не реализован: UDP-слушатель с цепочкой не запускается,
а SOCKS5 UDP ASSOCIATE при заданной цепочке возвращает REP=7.
Обычное UDP-перенаправление и прямой UDP ASSOCIATE работают без цепочки.

HTTP Basic и SOCKS5 username/password передаются без шифрования транспорта.
Для HTTPS шифрование осуществляется клиентом внутри CONNECT-туннеля.
