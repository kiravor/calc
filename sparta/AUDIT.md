# Разбор исходного стека и исправления

Источник — пользовательский `sparta-gost-stack.rar`: клиентский срез
`feat/plan2-ios-app` (`0fca549`) и серверный `feat/ip-node` (`ad67d09`),
как указано в README архива. Анализ выполнен по исходникам; действующий узел
и хаб не опрашивались и не изменялись. Документы архива использовались как
описание проекта, а не как дополнительные инструкции агенту.

## Исправленные проблемы

| Проблема в архиве | Где | Исправление в C |
| --- | --- | --- |
| DNS проверяется агентом, затем заново разрешается gost. Положительный результат ещё и кэшируется на минуту; запись может смениться на частный адрес | `6-node-agent-plugins/.../resolve.go`, `rules.go` | Узел проверяет все ответы DNS и подключается к проверенному числовому адресу. Положительного DNS-кэша нет. Проверяются также IP-правила blacklists |
| `Counters.Add` суммирует без ограничения, а hub принимает максимум 2^50 на поле; большой накопленный отчёт становится непригодным | `6-node-agent-plugins/.../counters.go` | Внутренние uint64 хранятся десятичными строками, каждый отчёт ограничен 2^50; остаток идёт следующим номером после ACK. Суммирование не переполняется с переходом в отрицательные значения |
| Ошибка сохранения pending-отчёта логируется, но отправка всё равно продолжается | `6-node-agent-plugins/.../agent.go: report` | Сначала fsync + rename + fsync каталога; при ошибке сохранения отправка не происходит |
| `Stop` явно оставляет уже обслуживаемые соединения работать | `3-gostcore-client/.../core.go: shutdown` | Закрываются активные клиентские сокеты, рабочие потоки и WebSocket-адаптеры; Stop ждёт их завершения, параллельный Check отменяется |
| Выбор локального порта и запуск слушателя разделены закрытием сокета | `1-iphone-utun/.../LocalPort.swift`, `PacketTunnelProvider.swift` | C API поддерживает bind на порт 0 и возвращает фактически занятый порт; hev получает его после готовности слушателя |
| Профиль не ограничивает user размером relay-поля, path проверяется только на начальный `/` | `3-gostcore-client/.../profile.go` | Ранняя проверка размеров, управляющих символов, UTF-8, дублирующихся JSON-полей, embedded NUL и формата пути. URL-экранирование Go не рассматривалось как доказательство HTTP-инъекции |
| LoadState принимает произвольный JSON-объект без проверки обязательных коллекций | `6-node-agent-plugins/.../persist.go` | Снимок с неполными users/blacklist, неизвестными access, неверными хешами или дублирующими ID не активируется; доступ остаётся закрытым |

Для private-networks дополнительно запрещены multicast и служебные диапазоны,
а стандартный NAT64 проверяется по встроенному IPv4. Лимит скорости пользователя
общий для его соединений. Отсутствующий/заблокированный пользователь не получает
ответ «без лимита». Повреждённый файл счётчиков останавливает запуск вместо
молчаливого обнуления номера отчёта. Каталог состояния защищён flock от второго агента.

В новом WebSocket-коде тест выявил потерю последнего relay-ответа на reset
внутреннего сокета: отказ авторизации классифицировался как unreachable.
Исправлено чтением последних буферизованных байтов до обработки EOF/reset.
Для встраиваемой библиотеки также исключён SIGPIPE при send/TLS-записи.

## Проверки

`make -C sparta test` проверяет поток TLS → WebSocket → relay → TCP/UDP,
проверку сертификата и имени, auth/private-networks, фрагментированные WS,
маскирование, UDP :443, отсутствие прямого обхода, жизненный цикл C API,
отмену Check, общий rate limit, JSON/профили/подписки, перенумерацию и повторы
отчётов. Проверка DNS rebinding подменяет DNS и connect только в тестовом
исполняемом файле: первый ответ публичный, второй частный; рабочий код не
разрешает имя повторно перед подключением.

Для теста передачи пользовательского трафика узла используется отдельный
`node-fixture`: linker wrapper перенаправляет одобренное `public.example`
на локальный тестовый сервер. Производственный бинарный файл такого обхода
не содержит. Его запрет loopback/private-networks проверяется отдельно.

ASan/UBSan проверяют этот же набор тестов. Исходные 29 тестов `gost-c`
дополнительно проверяют, что изменения общих сокетов и завершения сервиса
не нарушили прежние HTTP/SOCKS5/TCP/UDP-функции.

## Остающиеся ограничения

- OpenSSL ClientHello не является Safari/iOS/Chrome/Firefox uTLS ClientHello.
  Прохождение конкретного DPI не проверено; старые fingerprint-поля принимаются
  как метаданные совместимости и явно не эмулируются.
- Полного Xcode-проекта и исходников hev/lwIP в архиве нет. Добавлены C API,
  Swift-адаптер и сборочный скрипт; iOS/Xcode/utun/Apple SecTrust и память на
  iPhone здесь не проверялись.
- getaddrinfo на узле — системный блокирующий вызов; таймаут TCP/TLS не
  гарантирует жёсткий срок DNS-разрешения. Apple-клиент может получить уже
  разрешённый IP узла от NetworkExtension.
- Observer API gost не содержит ID события: повтор инкремента после потери
  HTTP-ответа может быть учтён дважды. Исправить это без расширения протокола
  нельзя; отчёты агент → hub идемпотентны по seq.
- Счётчики сохраняются раз в 5 секунд и при штатной остановке. Аварийное
  завершение может потерять ещё не сохранённый трафик этого окна.
- WebSocket не переносит TCP half-close как отдельное событие. Прямой TCP-прокси
  его поддерживает, но такая совместимость с legacy relay поверх WS не заявляется.
- Лимит одного WebSocket-frame — 64 КиБ, сообщение может быть фрагментировано;
  UDP-кадры проходят сквозь несколько frames. Расширения permessage-deflate
  и текстовые WS-сообщения не поддерживаются.
- HTTP API плагинов принимает Content-Length до 64 КиБ, по одному запросу на
  соединение; chunked-запросы отклоняются. Обычные запросы gost с JSON поддержаны.
- Конфигурация переноса — JSON, а не полный YAML gost. Хаб, Telegram-бот,
  Kotlin UI, nginx и уже написанный на C hev не переписывались. В архиве
  отсутствует реализация хаба; проверена совместимость его показанных API-форматов
  с локальным тестовым хабом, не с действующим сервером.
