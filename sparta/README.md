# Sparta на C

Перенос сетевого ядра и агента из `sparta-gost-stack.rar`. Один бинарный файл
`sparta` работает как клиент, relay-узел или HTTP-агент. Прежний `gost-c`
остаётся отдельным инструментом. Разбор ошибок: [AUDIT.md](AUDIT.md).

```text
hev/приложение → SOCKS5 → C-клиент → TLS/WebSocket → nginx → C-relay → сайт
                                                        ↘ C-правила, лимиты, учёт → hub
```

## Сборка

Нужны C17, pthreads, Make, pkg-config, OpenSSL 3 и libcurl 7.85+.
cJSON v1.7.19 включён в `vendor/` с MIT-лицензией. Go не нужен.

```sh
make -C sparta -j2
make -C sparta test
make -C sparta sanitize
# Обычная сборка после санитайзеров:
make -C sparta clean
make -C sparta -j2
```

`sparta/build/sparta --help` — справка. Для тестов нужны Python 3.8+,
openssl CLI и разрешённые loopback-сокеты. Внешние узлы не используются.
`build/libsparta.a` содержит весь стек; `build/libsparta-client.a` — клиент
без агента/libcurl (собирается целью `build/client-probe` и во время тестов).

## Клиент

Создайте профиль по [примеру](examples/profile.json), пароль храните отдельно
в файле с правами 0600. Существующие `sparta://import/v1/...` и
`sparta://sub/v1/...` также принимаются.

```sh
sparta/build/sparta client --profile profile.json --password-file password.txt
sparta/build/sparta client --link 'sparta://import/v1/BASE64URL'
sparta/build/sparta client --subscription 'sparta://sub/v1/BASE64URL' --node name
```

По умолчанию клиент поднимает SOCKS5 на 127.0.0.1:1080, проверяет 204 через
туннель, затем работает до SIGINT/SIGTERM. `--check-only` завершает процесс
после проверки. `--skip-check` запускает слушатель без проверки связи.
`--socks-port 0` резервирует свободный порт; адрес выводится в stderr.
Для локальной авторизации: `--socks-user USER --socks-password-file FILE`.
Для собственного CA: `--ca FILE`; отключения проверки TLS нет.
Для заранее разрешённого узла: `--node-address IP:PORT`, при этом имя и
исходный порт профиля сохраняются для SNI/Host/сертификата.

Поддерживаются TCP CONNECT и UDP ASSOCIATE. DNS назначения не разрешается на
клиенте: передаётся доменное имя. UDP :443 отбрасывается. При недоступности
узла прямого подключения к назначению нет.

TLS использует **native OpenSSL**, без браузерного uTLS-отпечатка.
Старые fingerprint safari/ios/chrome/firefox принимаются для чтения профилей,
но не меняют ClientHello. CLI явно сообщает это при запуске.
Для новых профилей используйте `"fingerprint":"native"`.

Коды выхода: 0 — успех/штатная остановка, 1 — ошибка связи, 2 — конфигурация,
3 — подписка недоступна. Check классифицирует ошибки как auth/tls/timeout/unreachable.
Входные профили и ключи не печатаются.

## Relay-узел и агент

Используйте [node.json](examples/node.json): укажите адрес хаба, ID узла,
путь WebSocket и доступные клиентам параметры в поле `node`.
Ключ хаба задаётся переменной `SPARTA_NODE_KEY`.
В регистрационном поле `node.fingerprint` примера оставлено `safari` для
совместимости со старым хабом и Go-клиентами; это не включает эмуляцию в C-клиенте.

```sh
sparta/build/sparta node --config node.json
# Отдельный агент для совместимости с существующими HTTP-плагинами gost:
sparta/build/sparta agent --config node.json
```

`node` объединяет relay, правила авторизации, ограничения скорости и учёт
в одном процессе. На нём не нужен отдельный gost или агент-плагин для
собственного data plane. Если нужен HTTP API `/auth`, `/limiter`, `/bypass`,
`/observer`, задайте `plugins_enabled:true` и переменную `SPARTA_PLUGIN_TOKEN`
длиной от 32 байт. У отдельной команды `agent` этот API включён всегда.
Один каталог состояния может принадлежать только одному процессу; запускать
`node` и `agent` с одним `state_dir` нельзя.

Снимок `state.json` берётся из хаба или из существующего каталога агента.
Без корректного снимка никто не авторизуется. Хаб получает PUT /v1/node,
GET /v1/state с ETag и POST /v1/report с seq. Сбой сети не открывает доступ
и не отбрасывает неподтверждённые отчёты. Повреждённые counters.json нужно
восстановить: программа не обнуляет их молча.

Новый counters.json хранит внутренние uint64 десятичными строками; старые
числовые файлы читаются. На hub уходят обычные JSON-числа в диапазоне до 2^50.
Это изменение формата совместимо на чтение с переносом, но не со старым Go-агентом:
для отката сначала сохраните исходные state/counters файлы отдельно.

Узел отвергает private/service/multicast назначения, локальные одиночные
имена, глобальные и пользовательские blacklists. Проверяются имя и все его
DNS-адреса; соединение устанавливается с уже проверенным адресом. Лимиты
скорости суммируются по соединениям одного пользователя. Изменение access
закрывает активные соединения после обновления состояния.

TLS терминирует nginx: [пример](deploy/nginx.conf.example) совместим с
локальным `127.0.0.1:8080`. Оставьте обновление сертификатов в существующей
инфраструктуре. [Dockerfile](deploy/Dockerfile) — заготовка для сборки из корня
репозитория; при использовании контейнера адрес `listen` внутри JSON должен
быть доступен nginx по сети контейнеров. Docker/nginx здесь не запускались;
пример требует адаптации путей сертификатов, сетей и конфигурации оператора.
Для команды `docker build -f sparta/deploy/Dockerfile .` включён отдельный
`Dockerfile.dockerignore`, исключающий сборки, ключи и локальное состояние.

## iOS и границы проверки

Публичный C API: [sparta.h](include/sparta.h). Интеграция:
[ios/INTEGRATION.md](ios/INTEGRATION.md), Swift-адаптер и сборка XCFramework.
Системная часть NetworkExtension/Keychain остаётся в существующем приложении.
hev/lwIP уже написаны на C и не переписывались.

Linux-клиент, сервер, агент и C API проверены локально. Работа с вашим VPS,
конкретным DPI, Xcode, utun и лимитом памяти расширения на iPhone не проверена.
Остальные отличия и ограничения перечислены в [AUDIT.md](AUDIT.md).
